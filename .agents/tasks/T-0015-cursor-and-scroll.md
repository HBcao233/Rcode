## 背景

T-0027 完成后，编辑器只能用方向键移动光标，视口只会被动跟随光标，没有手动滚动，也不能点击定位（见 T-0027 交接记录“已知限制”）。只要文本超过一屏或某行比屏幕宽，用户就看不到、也够不着这部分内容，触屏设备上基本不能用。

本任务给 `EditorView` 补上两项最基本的触摸交互：

1. 上下左右滚动视口（目前未开启软换行，Q7 默认关闭，所以需要横向滚动）。
2. 单击编辑区，把光标移到点击位置。

关联目标：`goals.md` 中的核心编辑体验；`decisions/0002-editor-ime-androidview.md`（自定义 View + Canvas + InputConnection）。

## 范围

### 包含

- **滚动**
  - 单指拖动时视口跟手平移，纵向和横向都支持。
  - 松手后惯性滑动（fling），可被下一次按下打断。
  - 滚动位置以像素为单位，不按整行对齐。拖动过程中允许部分可见的行出现在顶部和底部。
  - 滚动边界：
    - 纵向 `0 ≤ scrollY ≤ max(0, lineCount × lineHeight − 内容区高度)`。
    - 横向 `0 ≤ scrollX ≤ max(0, 最长行宽度 − 内容区宽度 + 光标宽度)`。“最长行”的取法见“待确认”。
  - 只绘制可见行（加上下预取），绘制时按 `scrollX` / `scrollY` 平移；`onDraw` 中仍然不能调用 FFI，也不能每帧分配对象。
  - 光标跟随规则调整：
    - 编辑（输入、删除、换行、IME 提交）、方向键移动光标、视图尺寸变化（例如软键盘弹出）之后，把视口最小幅度地滚到光标可见（纵横两个方向）。
    - 用户手动滚动后，即使光标已移出视口，也不能自动滚回去，直到下一次编辑或光标移动。
- **点击定位光标**
  - 单击（按下到抬起位移不超过 touch slop，且不是 fling）时，把光标移到点击位置。拖动和 fling 不移动光标。
  - 点击坐标换算为文档位置：
    - 行：`floor((y + scrollY − paddingTop) / lineHeight)`。
    - 列：在该行文本中取离点击 x（加上 `scrollX`、减去 `paddingLeft`）最近的字符边界，以字符宽度中点为界。
  - 点在某行文本末尾之后（行右侧空白）：光标移到该行末尾（换行符之前）。
  - 点在左侧 padding 区：光标移到该行行首。
  - 点在文本行数不够填满屏幕而留下的空白区（最后一行下方）：光标移到最后一行末尾，也就是文档末尾。
  - 光标不能落在 UTF-16 代理对或 UTF-8 多字节字符中间。最终位置以 Rust `move_cursor` 返回的字节偏移为准。
  - 点击时如果有组合文本（composing），先结束组合（保留已显示的文本，与 `finishComposingText` 一致），再移动光标。
  - 光标移动后，通过 `InputMethodManager.updateSelection` 通知输入法新的选区（UTF-16 偏移），避免输入法的上下文与文档不一致。
  - 保留原有行为：点击时请求焦点并弹出软键盘。
- **测试**：把坐标到文档位置的换算抽成纯 Kotlin 逻辑（例如 `EditorHitTester`，通过注入的宽度测量函数计算），方便在 JVM 单元测试中覆盖；滚动边界的计算同样抽成可测试的纯函数。

### 不包含

- 选区：长按选词、拖动选区手柄、双击选词、选区高亮、复制粘贴菜单（T-0015）。
- 双指缩放、改字号（T-0021）。
- 滚动条、快速滚动拖块、过度滚动的边缘光效。
- 行号栏、软换行（T-0021）。
- 鼠标滚轮、触控板、外接键盘 PageUp/PageDown/Home/End（可另开任务）。
- grapheme cluster 级别的光标定位：本任务按 Unicode scalar 处理，与 M1.0 一致，组合 emoji 等可能停在簇中间，作为已知限制记录。
- 屏幕旋转或切后台后恢复滚动位置：只要求光标位置保持（A0.3），且恢复后光标可见。
- 大文件滚动性能（A2，T-0014 / T-0025 负责）。

## 待确认

- [x] **Q-T15-1 横向滚动范围中“最长行”的取法**：
  - 取当前已加载行（视口加预取）中最宽的一行（由 Rust FFI 提供），纵向滚到较短的行时横向范围不收缩。
- [x] **Q-T15-2 点击时是否弹出软键盘**：沿用 M1.0 的行为，每次点击都调用 `showSoftInput`。如果用户已经手动收起键盘，点击定位时弹出键盘（与常见编辑器一致）。

## 测试方案

- Kotlin 单元测试：`./gradlew :app:testDebugUnitTest`
  - `EditorHitTesterTest`：ASCII / CJK / emoji / 空行 / 行尾右侧 / 左侧 padding / 留白区 / 空文档 / 带滚动偏移。
  - 滚动边界计算：内容比视口短、刚好相等、更长，横纵两个方向。
- Rust：如果只用现有的 `move_cursor`，不需要新增测试；如果新增 FFI（例如最长行宽度或行长度查询），先补 Rust 单元测试，再运行 `cargo fmt` / `clippy` / `test`。
- 仪器测试（可选，需要设备）：`./gradlew :app:connectedDebugAndroidTest`，用注入 MotionEvent 的方式验证点击定位和拖动不移动光标。
- 手动验证（真机）：逐项过 S1–S4、C1–C6，记录设备型号与输入法名称。
- 基准：不涉及；大文件滚动帧率留给 T-0025。


## 验收标准

- [ ] S1 纵向滚动：输入超过一屏的文本（例如 200 行）后，上下拖动能看到首行和末行；滚到顶部或底部时停在边界，不越界、不回弹出空白（真机 + 单元测试覆盖边界计算）。
- [ ] S2 横向滚动：输入一行超过屏幕宽度的文本后，左右拖动能看到行首和行尾；所有行都比屏幕窄时不能横向滚动（真机 + 单元测试）。
- [ ] S3 惯性滑动：快速滑动后视口继续减速滚动，并停在边界以内；滑动中按下会立即停止（真机）。
- [ ] S4 跟随光标：手动把光标滚出视口后，输入一个字符或按方向键，视口会滚到光标可见；只滚动不编辑时，视口不会自动跳回（真机）。
- [ ] C1 点击定位：点击某行中间的字符时，光标落在离点击位置最近的字符边界上（JVM 单元测试覆盖 ASCII、CJK、emoji（代理对）、空行；真机验证）。
- [ ] C2 行尾：点击某行文本右侧的空白时，光标移到该行末尾（单元测试 + 真机）。
- [ ] C3 留白区：文本行数不够填满屏幕时，点击最后一行下方的空白，光标移到最后一行末尾，也就是文档末尾；文档为空时光标在偏移 0（单元测试 + 真机）。
- [ ] C4 滚动后点击：横向或纵向滚动后再点击，光标位置仍然正确，换算时计入了 `scrollX` / `scrollY`（单元测试 + 真机）。
- [ ] C5 拖动不移动光标：拖动或 fling 结束时光标位置不变（真机；如可行，加仪器测试）。
- [ ] C6 组合输入：中文拼音组合过程中点击别处，组合文本被提交（不残留下划线、不重复、不丢字），光标移到点击位置，之后继续输入正常（真机，至少一款系统输入法）。
- [ ] 回归：A0–A0.3 的行为不变（英文/中文输入、退格、回车、方向键、旋转与切后台）。
- [ ] `onDraw` 中没有 FFI 调用，也没有每帧分配对象；Kotlin 不持有全文副本。
- [ ] DoD 全部通过；涉及 UI，交接记录附真机截图或录屏说明；更新 `CHANGELOG.md`。
