# 项目目标

## 1. 项目定位

Rcode（暂定名）是一款 **仅面向 Android** 的移动代码编辑器。
UI 设计参考 Acode 的信息架构（文件树、标签页、底部/侧边工具、设置页），但代码从零实现，不复用 Acode 代码与资源。

## 2. 核心目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 原生体验 | 使用 Jetpack Compose 构建 UI，不使用 WebView 承载编辑器或主界面 |
| G2 | 性能 | 大文件（≥10 MB）可打开、滚动流畅；冷启动和内存优于 WebView 方案 |
| G3 | 核心逻辑可复用 | 文本缓冲、搜索、语法高亮、LSP 等放在 Rust 核心库中，便于测试与后续复用 |
| G4 | 可靠保存 | 编辑内容不因崩溃、切后台、被系统杀进程而丢失 |
| G5 | 可被 agent 持续开发 | 目录、规范、任务单、skill 清晰，agent 可独立完成小任务并可验证 |

## 3. 非目标（当前阶段明确不做）

- iOS、Windows、Linux、Web 版本
- 兼容 Acode 插件或 JS 插件 API
- 内置 Alpine 终端、SSH/SFTP（放入 M5 之后再评估）
- 广告系统、应用内购买（先保持纯净，后续单独决策）
- 云同步、账号体系
- 自研完整 IME 替代方案（优先使用系统输入法框架，必要时再深入）

## 4. 目标用户

- 在手机或平板上做轻量编辑、查看代码、修改配置的开发者
- 需要快速查看日志、文本、小型项目的用户

## 5. 成功指标

| 指标 | 目标值（初版） | 测量方式 |
|---|---|---|
| 冷启动到可编辑（中端机） | < 1.0 s | Macrobenchmark / 手动计时 |
| 打开 10 MB 文本首屏 | < 500 ms | 基准测试（perf-benchmark skill） |
| 滚动掉帧率（10 MB 文件） | < 5% 帧超过 16 ms | Frame timing |
| 空闲内存（打开 1 个文件） | < 150 MB | Android Studio Profiler |
| 崩溃率（内测） | < 0.5% 会话 | 崩溃上报 |
| 数据丢失事件 | 0 | 回归测试 + 手动用例 |

这些数值是初始假设，M1 结束时需用真实数据校准并更新本表。

## 6. 约束

- 最低支持 Android 7.0（API 24），目标 SDK 以当前 Play 要求为准。
- 开发环境以 Linux/Termux 或桌面 Android Studio 为主；CI 使用 GitHub Actions。
- 许可证：项目采用 MIT、Apache-2.0 双许可证开源。引入依赖前必须检查许可证（见 `conventions.md`）。
