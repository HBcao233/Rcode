## M1 核心编辑器（约 4–6 周，人力估算）

目标：能打开、编辑、保存一个文件，并能正确显示语法高亮。

### 1.1 范围

包含（功能来自原路线图，未增减）：
- 文件选择（Storage Access Framework）
- 打开/保存文本文件（UTF-8，自动检测 BOM 和换行符 LF/CRLF）
- 文本缓冲区（Rust，rope 结构），支持撤销/重做
- 自定义绘制编辑器视图（仅绘制可见行）
- 基础语法高亮（tree-sitter：至少 Kotlin、Rust、JSON、Markdown、Python）
- 软换行开关、行号、字号调整
- 自动保存草稿（崩溃恢复）

不包含（留给后续里程碑，避免 M1 膨胀）：
- 多标签、文件树、文件夹级搜索、主题切换、设置页（M2）
- LSP、诊断、补全（M3）
- 非 UTF-8 编码的读写（见 backlog 待确认 Q1）

### 1.2 实施顺序（依赖图）

M1 分两段推进。第一段（M1.0 最小编辑器纵切）是进入 M1 后的第一步：启动即进入编辑界面，可用输入法输入文本，但暂不涉及文件读写。

**M1.0 最小编辑器纵切（第一步，必须先完成）**：
- 启动应用直接进入编辑界面，内容为内存中的 `untitled.txt`（无文件选择）
- 输入：软键盘英文输入、中文输入法（拼音等）组合输入、删除、回车、方向键
- 只需保证进程存活期间内容正确；未保存、进程被杀的数据丢失由 M1 后续任务（草稿）处理
- 不包含：撤销重做、语法高亮、SAF、保存、rope（使用临时实现，T-0007 替换）

```
[M1.0]  启动即编辑 untitled.txt ── 输入法（InputConnection）── 最小 Canvas 渲染
                  │
[Rust 层]                         [FFI]              [Android 层]
buffer ──► undo/redo ──┐
  │                    ├──► 编辑会话 FFI ──► 文件打开(SAF) ──► 可见行渲染 ──► 光标/选区 ──► IME
codec(BOM/换行) ───────┘        │   │                 │                              │
                                │   └──► 原子保存 ────┘                              │
                                │                                                   │
syntax(框架+Rust/JSON) ─► 其余语言 ─┴──────────────► 高亮接入渲染                  │
                                                                                    │
草稿保存 ──► 草稿恢复（进程被杀验证）                            软换行/行号/字号 ◄─┘
                                                     端到端 UI 测试 ◄── 保存 + 输入
                                                     性能验收（10 MB）◄── 渲染 + 高亮
```

任务编号与状态见 `tasks/backlog.md` 的 “Ready（M1）” 与 “Backlog（M1）”。

### 1.3 验收标准（细化后，可测量）

| 编号 | 验收项 | 判定方法 |
|---|---|---|
| A0 | M1.0：冷启动后直接显示 `untitled.txt` 编辑界面，无需任何操作 | 手动用例 + Compose UI 测试 |
| A0.1 | M1.0：英文软键盘输入、删除、回车、方向键，显示与预期一致 | 手动用例（真机）+ 仪器测试（如可行） |
| A0.2 | M1.0：中文输入法（拼音）组合输入时显示组合文本（下划线），选词提交后内容正确，取消组合不残留 | 手动用例（真机，至少一款系统输入法） |
| A0.3 | M1.0：屏幕旋转、切后台再回来，内容与光标位置保持 | 手动用例 |
| A1 | 10 MB UTF-8 文本，从用户选定文件到首屏文本绘制完成 < 500 ms | Macrobenchmark，或 tracing span 计时；中端机，测试文件构成见 backlog 待确认 Q10 |
| A2 | 10 MB 文件滚动时 > 16 ms 的帧 < 5% | Frame timing（Macrobenchmark） |
| A3 | 打开 1 个 10 MB 文件后空闲内存 < 150 MB | Android Studio Profiler |
| A4 | 缓冲区属性测试：随机编辑序列后，与 `String` 参考实现的文本、行数、行内容、字符/字节转换完全一致 | `proptest`，每次 CI 至少 1000 个用例 |
| A5 | 撤销/重做：对任意编辑序列，全部 undo 后回到初始文本；全部 redo 后回到最终文本；新编辑清空 redo 栈 | `proptest` + 单元测试 |
| A6 | 保存往返一致：未编辑的 UTF-8 / UTF-8 BOM / LF / CRLF 样本，打开后保存，字节与原文件完全一致 | 样本 fixture 测试（Rust）+ 仪器测试（Kotlin） |
| A7 | 编辑后保存：内容与缓冲区一致；保存失败时原文件内容不变 | 仪器测试（注入失败） |
| A8 | 草稿：编辑后进程被杀（`adb shell am force-stop` 或等效手段），重新打开应用出现恢复提示，恢复内容与杀前一致 | 手动用例 + 仪器测试 |
| A9 | 草稿写入中途失败，不破坏上一份有效草稿 | 单元测试（模拟写入失败） |
| A10 | 高亮：每种语言的快照（`insta`）稳定；增量重解析结果与全量解析结果一致 | `insta` 快照 + `proptest` |
| A11 | 编辑、撤销、保存、高亮在 M1 结束时，Rust 核心覆盖率 ≥ 80%（buffer / codec / syntax） | `cargo llvm-cov`（工具引入需走依赖检查，见 backlog 待确认 Q12） |
| A12 | 关键用户流程 Compose UI 测试通过：打开文件 → 输入 → 撤销 → 保存 → 重新打开核对内容 | Compose UI Test（仪器测试） |
